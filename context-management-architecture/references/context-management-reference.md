# 上下文组装与恢复

用于信息归属、模型输入、压缩与持久化决策。以下是职责划分，不要求部署成固定层数或独立服务。

## 信息归属

| 内容 | 主要职责 | 进入模型的方式 |
| --- | --- | --- |
| 可信指令 | 产品行为、权限和工具使用规则 | 稳定指令；明确版本与变更来源 |
| 当前输入 | 用户消息、当前时间、页面、附件引用 | 当前任务所需字段，按调用需要刷新 |
| 对话历史 | 保持连续性与必要工具上下文 | 单一组装来源，按预算保留或压缩 |
| 运行状态 | 执行进度、待确认动作、恢复位置 | 应用保存，仅投影任务需要的信息 |
| 外部事实 | 订单、政策、文件等权威数据 | 按权限、任务和新鲜度获取 |
| 长期记忆 | 跨会话可复用信息 | 通过记忆服务返回最小有效投影 |
| 产物与前端状态 | 用户操作、结果引用和展示 | 只回传必要数据，不注入无关界面事件 |

session 可以持久保存而不成为长期语义记忆；存储寿命、作用域和进入模型的内容是不同维度。复用既有框架 state/store 即可满足需求时，不额外拆服务。

## 每次模型调用的组装

```text
当前任务与运行状态
  -> 获取本次所需事实和记忆投影
  -> 选择历史/摘要，校验来源、权限、新鲜度与预算
  -> 可信指令 + 任务输入 + 必要数据
  -> 模型提出工具调用
  -> 应用校验并执行，记录结果与恢复信息
  -> 按下一次调用的需要重新组装上下文
```

- 平台托管历史与应用历史重放选择明确的组装职责，避免重复消息和工具结果。
- 托管历史指针不等于历史已经压缩或没有 token 成本；按实际平台能力评估。
- 动态信息放稳定缓存前缀之后，不为缓存牺牲新鲜度。
- 历史中的工具调用与结果按目标 API 保持配对；大结果裁剪或外置为可重新读取的引用。
- 用户消息、来源资料与应用生成的事实分开标记；不能把客户端提供的 user/tenant/确认字段直接当可信授权。

## 来源与指令权限

按事实归属判断权威性：用户可更正自己的偏好，订单状态与权限由业务系统决定，新网页不自动胜过旧的权威记录。

第三方材料、工具结果和抽取记忆是数据；摘要和持久化不得提升其权限。仅经产品认可的规则更新流程才可修改可信指令，数据格式校验不能代替这一边界。按具体模型接口使用可区分来源的数据或工具结果容器。

## 预算与压缩

按模型窗口、输出需求和工具循环预留空间，每次调用检查预算；触发阈值依据任务轨迹验证，不固定 token 比例。

压缩保留当前目标、约束、已完成进度、未解决问题和必要来源引用；授权与副作用状态从应用记录核实，不以摘要作为唯一依据。

`loaded_reference_ids` 只表示读取历史，不证明文本仍在当前窗口。记录或计算当前可见内容；摘要丢失关键细节、资料版本变化或新任务需要时允许重新获取。测试压缩后的行为，而不只检查摘要是否生成。

## 持久化边界

| 恢复要求 | 可选策略 | 代价与限制 |
| --- | --- | --- |
| 可整体重跑的短任务 | 结束时持久化 | 进程崩溃可能丢失中间进度 |
| 可接受少量进度丢失 | 异步检查点 | 存在未落库窗口 |
| 必须从明确位置恢复 | 关键步骤同步检查点 | 增加延迟和存储成本 |

使用框架持久化能力时核实其语义；业务事务、运行检查点与前端重连不是同一种机制。需要人工等待的动作在等待前保存对象、参数版本和授权范围。

## 副作用结果与恢复

执行前核实身份、权限、对象版本与有效授权；已有授权不重复确认。自然语言“确认”只有绑定到明确动作后才可继续。

重试使用与同一业务操作绑定、可从持久状态重建的幂等键，并确认下游确实支持去重。外部请求超时或响应丢失时，结果记为未知，先查下游状态；无法确定时向用户说明，不盲目重新执行或宣称未执行。

并发更新使用框架支持的版本检查或串行化策略；恢复到旧检查点也要防止重复副作用。
