# 事件与状态契约

用于事件适配和状态更新。先核实项目使用的 SDK、协议版本与既有状态模型；已有客户端契约可用时直接复用，不另造一层协议。

## 事件含义

以下是应用需要区分的含义，不是强制事件名：

| 含义 | 更新方式 | 不能据此推断 |
| --- | --- | --- |
| 工具参数增量 | 按调用 ID 拼接片段 | 参数已完整或工具已执行 |
| 参数生成结束 | 解析并校验完整参数 | 已获授权或已开始执行 |
| 工具开始执行 | 按执行端状态更新工作项 | 已成功 |
| 工具结果 | 记录成功、失败或结果不明 | 整个任务已完成 |
| 消息结束 | 结束当前消息的增量 | 后续没有工具或模型调用 |
| run 结束或暂停 | 读取状态、结束原因和 outcome | 用户目标一定已达成 |
| 连接关闭 | 标记连接状态并查询运行状态 | run 失败、成功或已取消 |

AG-UI 的 `TOOL_CALL_ARGS` 是参数片段；`TOOL_CALL_END` 表示调用参数传输结束，不能替代执行端确认。自定义“参数已就绪”事件应另起名称。对支持 interrupt outcome 的版本，`RUN_FINISHED` 可能表示等待用户后续恢复；按版本和 outcome 映射，不能一律显示“已完成”。

## 标识与合并

- 以 `run_id`、`message_id`、`tool_call_id`、`artifact_id` 或框架等价标识关联数据；同一工具调用的阶段更新同一个工作项。
- 并行调用分别归属各自 ID；涉及子运行时保留父子关系，子运行结束不结束父运行。
- 框架无调用 ID 时，使用运行 ID 加稳定输出索引等可重建组合，不用每个 chunk 的到达时间生成新 ID。
- 支持重放时，使用协议提供的事件 ID、游标或序号去重；工作项 ID 本身不能防止文本 delta 被重复追加。
- 区分重连、重试执行与新调用；需要区分尝试次数时再增加 attempt 标识。

## 过程文本与最终结果

优先使用应用提供的消息用途、阶段和最终结果标记。只有无标记的单一串行循环才考虑临时文本策略：先显示为待定，获得明确用途后再归类。后续出现工具调用并不要求把此前所有文本移动或隐藏。

任务状态来自执行端，文字位置来自产品设计；最终产物可以没有最终文本，也可以在后续工作开始前已经生成。不要用最后一条消息或“没有 tool call”代替业务完成条件。

## 恢复与终止

按任务区分 `running`、`waiting_for_user`、`succeeded`、`failed`、`cancelled`；传输状态单独记录。无需与某个框架的枚举名称相同。

重连先取得当前运行/消息快照，再从约定游标恢复增量；若使用框架恢复能力，遵从其快照与重放规则。恢复失败时提供查询状态或重新发起的路径，不凭空补齐成功状态。

取消请求与取消已生效分开；收到执行端确认后再标取消，迟到事件不能无条件把终止状态改回运行中。需要继续的暂停动作绑定原授权对象和版本，恢复不扩大权限。

副作用的授权沿用 [主文件](../SKILL.md)；外部执行结果不明时，先查询业务状态，避免重试重复执行。

## 渲染边界

结构化结果按类型和版本校验后渲染；只传递该用户可见且界面需要的字段。参数预览使用允许公开的字段，不暴露凭据、内部推理或完整数据库记录。工具错误与整个 run 失败分开，允许执行端恢复后继续。
