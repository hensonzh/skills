# 流式界面设计

用于布局与文案；事件含义和恢复规则以 [事件契约](event-contract.md) 为准。

## 先决定用户需要什么

明确最终产物、等待时有价值的信息、可介入动作与失败后的操作。已有明确需求时直接处理相关界面，不先填写完整问卷。

| 任务 | 可选界面 |
| --- | --- |
| 短问答 | 流式文本和轻量等待状态 |
| 多步骤工具任务 | 当前工作项，必要时展开历史过程 |
| 报告、草稿或表格 | 结果优先，操作靠近结果 |
| 需要额外授权 | 可检查的变更预览和明确确认动作 |
| 长任务 | 取消、后台继续或稍后查看，取决于执行端能力 |

聊天、工作面板、结果区、操作区是布局选项，不是必须同时存在的四块组件。复用现有消息 parts、卡片或侧栏即可表达时，不为分区重写界面。

## 文案与信息量

- 展示真实阶段和结果，不展示为了凑流程而编造的步骤或百分比。
- 未收到具体工作信号时使用“正在处理”等中性反馈；收到检索开始后才显示“正在查找资料”。
- 工具参数生成不等于查询已经执行；状态文案采用事件契约中的实际阶段。
- 不为每个结果再加一段口号或解释；布局、标题与按钮已经说明用途时省略辅助文案。
- 暂时停顿的反馈延迟根据实际时延和可用性验证选择，不固定毫秒阈值。

## 授权、错误与移动端

确认边界沿用 [主文件](../SKILL.md)：自动保存等已授权动作直接显示执行状态；需要额外授权时说明对象与变更，确认后继续。

工具失败先说明受影响的工作及可用操作，不直接宣告整个任务失败。断线显示状态暂不可知或正在重连；是否可以安全重试由执行端决定。

小屏幕优先展示结果与当前需要用户操作的内容；长过程可折叠。是否全宽卡片、固定操作区或默认折叠，按现有设计系统和任务验证。
