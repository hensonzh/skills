# 排障与验证

先定位异常对应的事件、标识、状态更新与渲染组件。局部问题只给局部修复，不要求完整产品 brief。

## 常见故障

| 现象 | 优先检查 |
| --- | --- |
| 同一次调用显示多行 | 调用 ID 是否稳定，start/result 是否更新同一项 |
| 参数还没完整就显示执行中 | 是否把参数增量或参数结束当成执行事件 |
| 工具结束就显示任务完成 | 是否混淆调用、消息、run 与业务结果 |
| 暂停等待确认却显示成功 | 运行结果或 interrupt outcome 是否被忽略 |
| 重连后文本重复 | 重放游标和事件去重是否正确 |
| 一直等待或突然空白 | 连接状态、运行状态和下一条可见事件是否分开处理 |
| 已授权动作反复确认 | UI 是否擅自增加了执行端没有的授权门槛 |
| 结果被过程淹没 | 是否展示了无用户价值的日志，结果位置是否稳定 |

事件规则只在 [event-contract.md](event-contract.md) 维护；布局选择见 [frontend-work-panel.md](frontend-work-panel.md)。

## 按改动选择验证场景

| 场景 | 可观察结果 |
| --- | --- |
| 参数 JSON 分成多个 chunk | 完整前不解析为可执行输入，不误报执行中 |
| 两个工具并行输出 | 结果归属正确，同次调用只更新一项 |
| 过程文本后继续调用工具 | 不提前结束任务，不丢失已有内容 |
| 仅产物完成，无最终文本 | 按运行结果完成界面，不无限等待文本 |
| 已授权自动保存 | 无新增确认，展示实际保存结果 |
| 运行暂停与恢复 | 等待状态及确认对象恢复，暂停不显示成功 |
| 工具失败后恢复 | 保留局部错误，允许执行端继续完成任务 |
| 重复事件、重连与刷新 | 快照和增量一致，文本不重复、结果不丢失 |
| 取消后收到迟到事件 | 不错误恢复运行中，不假报未执行的副作用已撤销 |
| 简单问答与小屏幕 | 反馈清楚，主要结果和必要操作可见 |

实现交付仅列涉及的事件/组件、授权边界和验证结果。设计审查区分已知问题与需要真实事件轨迹才能验证的假设；没有运行实现时不声称测试通过。
