# Agent Loop Streaming

## 按任务执行

- 体验设计：明确用户任务、等待时需要的信息、最终产物和失败后的操作，给出相关状态与文案。
- 实现或改造：先读现有流式链路，定义事件到 UI 的映射、状态转换、稳定 ID 和验收场景，再修改必要组件。
- 问题诊断：从异常状态追到对应事件和 reducer，给出最小修复与验证方式。
- 信息不足时标明可调整的假设；只追问会影响核心交互或执行权限的缺口。

## 实现约束

- 区分中间说明、工作状态、结构化结果和最终回答；用 `RUN_FINISHED` 或等价事件判断整个 run 完成。
- 将模型厂商事件适配为应用事件；围绕 `run_id`、`message_id`、`tool_call_id`、`artifact_id` 更新 UI。
- 同一次工具调用更新同一个工作项；文本后来伴随工具调用时仍属中间过程，不提前标记最终答案。
- 只展示真实且有用户价值的进度；工具名转为用户语言，隐藏凭据、原始参数和内部推理。
- 卡片等结构化结果从受校验的 payload 渲染；失败时说明下一步可做什么。
- 按既有授权和产品规则处理副作用；需要确认的动作展示预览并等待确认，已授权的动作不重复拦截。
- 简单问答只需轻量反馈；复杂任务再使用工作面板、结果区和操作区。

按任务输出相关状态、实现要点或诊断结果，不固定阶段数量或报告章节。
