# Agent Loop Streaming

## 执行规则

- 先读现有事件链路和界面；设计时明确等待信息与最终产物，排障时定位异常事件和状态更新。
- 复用现有 SDK 或应用协议，核实版本与事件语义；按稳定 ID 更新同一次调用或产物，不为每个增量新增一行。
- 区分参数生成、工具执行、消息结束与任务结果；按运行状态及 outcome 区分成功、失败、取消和等待用户，不把断流或单次模型响应结束当成功。
- 优先使用明确的消息用途区分过程与答案；没有用途标记时先保持待定，不仅凭后续是否调用工具决定最终答案。
- 只展示真实且有用的进度；工具名转为用户语言，结构化结果校验后渲染，隐藏凭据与内部推理。
- 副作用按既有授权执行；只有需要额外授权的动作才展示预览并等待确认，已授权动作不重复拦截。
- 简单问答使用轻量反馈；布局按产物和交互选择，不强制工作面板或四区布局。

只输出本次需要的设计、修复和验证；涉及恢复时验证重连、重复事件与取消后的状态。
