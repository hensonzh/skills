# Safe Git Merge

在执行 pull、merge、rebase、checkout、reset 等操作前，先检查：

- 当前分支和远端跟踪关系。
- 本地是否有未提交改动。
- 本地是否有未推送提交。
- 即将合并的远端提交会带来哪些变化。

不要使用会丢弃本地工作的命令，除非用户明确确认。

默认流程：`status` -> `log/branch` -> `fetch` -> 对比本地和远端 -> 再合并。

## 无冲突合并后自动推送

用户于 2026-11-02 确认此跨项目偏好：用户请求拉取并合并远程分支时，
若无冲突且相关检查通过，直接将合并结果推送到对应远程分支，不再单独询问
是否推送。即使远程已是最新、只有本地待推送提交，也按此流程同步。

- 用户当次明确要求仅拉取、仅本地合并或不推送时，以当次要求为准。
- 确认当前分支、跟踪关系和目标；目标无法从请求或跟踪关系确定时先澄清。
- 保留本地提交及未提交改动；使用普通推送，不强制覆盖远程历史。
- 出现冲突时，按已授权的仓库专属规则处理；其余冲突逐项确认，解决并检查
  通过后按该次确认的范围继续。不要把自动推送偏好理解为自动解决代码冲突。
- 检查失败时先处理任务范围内的问题；无法处理则报告阻塞，不推送失败结果。
  推送因远程更新被拒绝时，重新抓取、审查和合并，仍遵循冲突确认规则；若
  远程连续更新导致再次拒绝，报告状态，不无限重试或强制推送。
