# Safe Git Merge

## 同步流程

1. 检查分支、跟踪关系、未提交改动和未推送提交；确认目标，无法确定时询问。
2. `fetch` 后比较本地与远端，再选择合并方式。保留本地工作；丢弃或覆盖操作需用户明确确认。
3. 用户请求拉取并合并远程分支时，无冲突且相关检查通过后普通推送到对应分支；即使远端已最新、仅本地有待推送提交也适用。
4. 用户当次要求仅拉取、仅本地合并或不推送时照做；不把自动推送授权用于普通本地修改。
5. 冲突按已授权的仓库规则处理；其余冲突逐项确认，解决并检查后按该次授权继续。
6. 检查失败只修复任务范围内问题；无法解决则报告且不推送。远端更新导致拒绝时重新抓取、审查、合并；再次因远端更新被拒绝则停止，不强推。

## Cozie 已确认偏好

- 仅对 `deepcozy/lab_mobile` 及其工作树：合并远程 `main` 时，`AGENTS.md` / `AGENTS.override.md` 冲突采用本次抓取的 `origin/main` 版本，并报告采用的文件。
- 其他代码和业务逻辑冲突逐项确认，不使用全局 `-X theirs`。
- 个人需求确认由全局 `confirm-requirements` 维护，不重新写回项目指令。
