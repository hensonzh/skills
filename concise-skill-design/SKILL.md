# 简洁 Skill 设计

- 用一句话说明何时使用、解决什么问题；必要时补充容易混淆的边界。
- 每条只表达一个要求，写清“条件 → 动作 → 完成标准”；省略显而易见的条件。
- 使用明确动词、对象、路径或判断条件，替换“做好、合理、全面”等空泛要求。
- 主文件只保留执行必需的信息；教程、长示例和完整模板按需放入参考文件，注明何时读取。
- 同一规则只维护一处；删除重复解释、口号和无助于执行的历史背景。
- 将建议与硬性要求区分开；限制步骤、输出或确认流程时写明适用条件。
- 保留已确认的用户偏好、授权范围、数据保护要求和必要的失败处理。
- 按任务规模选择输出与检查；不强制每次填写完整模板，不用固定行数代替清晰度。
- 修改后检查触发描述、正文、参考文件和评估用例是否一致；结构校验按 skill-creator 执行。

审查时指出具体位置、执行影响和改法；只审查的请求不修改文件。
