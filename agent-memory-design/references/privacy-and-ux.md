# 授权、用户控制与删除

本文件负责记忆生命周期中的授权与删除边界；具体法律义务按产品适用要求核实，不用通用技术模板替代。

## 授权

- 分开“允许保存哪类信息”和“某条候选是否足够可靠”；置信度不能替代授权。
- 默认开关按用户预期、用途与敏感度确定，不因产品被称为个人助手或 B2B 就自动选择 opt-in/opt-out。
- 用户提及健康等高敏信息不等于授权长期保存；需相应明确授权。凭据使用专用密钥系统，不作为普通可检索记忆。
- 明确偏好与行为推断分开；未经允许不学习推断型信息，已允许的推断保留不确定性。
- scope 校验来自可信身份与权限，覆盖存储、搜索、导出和共享；共享不自动扩大到敏感类目。

## 查看与纠正

提供可理解的内容、来源以及更正、删除、关闭入口；内部 key、类型和 confidence 不必直接暴露给用户。需要解释来源时按权限展示必要片段。

用户可纠正错误推断或事件；界面可以收集更正并使原记录失效，不必开放所有内部字段，也不能只允许删除而拒绝更正。

显式记住、纠正或忘记请求反馈实际结果；后台学习不逐轮播报。暂停学习与删除已有记忆分开，当前对话仍可见的内容也要与长期记忆区分。

## 删除与防止重新写回

1. 根据请求定位内容和范围；对象明确且已授权时执行，指代不明时才澄清。
2. 按产品承诺选择软删、硬删或有期限的撤销流程；界面明确实际效果，不把仅隐藏条目说成彻底删除。
3. 停止相关记忆的有效检索，处理主存储、向量/全文索引、缓存及相关摘要副本；审计与备份按既定保留和恢复策略处理，不保留无必要的敏感原文。
4. 对异步提取、离线整理和重试校验删除/授权版本，必要时使用删除标记或处理水位，避免旧任务从历史中重建已忘记的信息。
5. 保留删除防护标识时仅存必要 metadata；撤销或用户再次明确记住时按新授权处理。

用户纠正后，下一次有效检索应使用新值；对仍在途的旧结果设置版本检查，不能只清缓存后让旧任务写回。

## 信任边界

记忆来源可能包含用户表达、第三方内容或模型摘要。保存、压缩和检索不得提升其指令权限；只允许应用认可的规则更新路径改变可信指令，写入接口仍检查范围和允许字段。

防护不只依赖 denylist 或模型判断，还包括来源标记、权限校验、受限写入和回归场景。[Anthropic 对不可信内容的处理建议](https://platform.claude.com/docs/en/test-and-evaluate/strengthen-guardrails/mitigate-jailbreaks)。
