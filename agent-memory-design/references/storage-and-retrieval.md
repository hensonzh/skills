# 记忆存储与检索

按查询和一致性需要选型，不把记忆分类直接等同于数据库类型。

## 存储选择

| 访问需求 | 可选实现 |
| --- | --- |
| 少量稳定设置，按 key 精确读取 | 现有设置表、KV 或结构化文件 |
| 多条记忆的过滤、更新和版本检查 | 带元数据的文档或关系存储 |
| 自由文本的相似经历检索 | 全文、向量或混合检索，按评估选择 |
| 跨实体关系查询 | 现有关系表；复杂查询确有需要时再用图存储 |

同一存储可以同时提供结构化过滤和向量查询；只有容量、延迟或隔离需求证明有必要时再分库。精确读取与相似检索语义不同，精确 key 未命中时不能拿相似条目冒充该值。

## 身份与更新

- 记录 ID、权限作用域、内容、来源和有效状态是基本信息；版本、过期时间、向量或审计引用按用途增加。
- 单值设置可对 `(tenant_id, scope_kind, scope_id, key)` 约束一个有效版本；事件型记忆通常按独立 `event_id` 追加，主题 key 不应兼作事件唯一身份。
- 作用域必须能够唯一标识授权主体；租户内用户 ID 不全局唯一时，查询和索引必须包含租户。
- 检索在权限范围内执行，再按相关性排序；角色或人格变化是否切换作用域由真实授权边界决定，不凭 UI 模式名称猜测。

## 检索与预算

1. 根据任务选择精确读取、过滤或搜索；不要求每次都扫描全部记忆类型。
2. 排除无权限、过期、已删除或失效信息。
3. 按相关性和用途选择新鲜度、来源质量等排序因素，限制条数与 token；权重和预算用任务效果验证，不固定输入占比。
4. 返回最小投影，明确来源与不确定性；无相关结果时返回空，不补造记忆。

自然语言摘要和结构化字段都可用，按消费者与任务选择；不要求前端展示、内部存储和模型输入使用相同 payload。

## 生命周期

保留期限取决于用途、授权和产品承诺，不按类型统一永久保存或套固定天数。读时排除到期记录，不能只依赖后台清理是否及时；写入、纠正和删除后的索引/缓存更新遵循同一可见性约定。

删除流程与旧任务写回防护只在 [privacy-and-ux.md](privacy-and-ux.md) 维护。

## 模型投影示例

```json
{
  "items": [
    {
      "memory_id": "mem_42",
      "kind": "preference",
      "value": {"language": "zh-CN"},
      "source_kind": "user_explicit"
    }
  ],
  "truncated": false
}
```

投影是数据，不是新增授权。推断保留假设标记和来源；只有经过产品认可的规则更新流程，才允许改变可信指令。需要证据时按权限读取必要片段，不默认附带完整原文。
