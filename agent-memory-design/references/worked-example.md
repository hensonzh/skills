# 示例：语言学习助手

这是一个已明确需要跨会话个性化的产品示例，不是通用默认架构。授权与删除沿用 [privacy-and-ux.md](privacy-and-ux.md)，抽取契约沿用 [extraction-pipeline.md](extraction-pipeline.md)。

## 本例的选择

- 用户开启学习记录；语言与回答风格来自设置，学习事件来自练习记录。
- 仅在用户允许学习模式分析后保留弱项推断；不推断健康或心理状态。
- 先用现有关系存储按用户、时间和主题读取；只有相似经历检索效果不足时再评估向量索引。
- 设置更新同步生效；课后摘要异步处理，记录来源版本；保留期限由本产品另行确定。

| 内容 | 身份与更新 | 读取 |
| --- | --- | --- |
| 回答语言 | 单值 preference key，设置更改时更新版本 | 回复任务相关时 |
| 课程摘要 | 独立 lesson/event ID，同主题可多条 | 最近课程或指定主题 |
| 语法弱项 | derived，关联练习证据与版本 | 复习任务中作为假设 |

## 写入与读取

```text
课后事件 -> 读取已授权的练习记录 -> 生成候选
  -> 校验 schema、证据、权限与版本
  -> 合并重复事件，追加不同事件，按冲突策略更新偏好/推断
  -> 后续检索过滤无权限、已删除和过期记录
  -> 返回与当前任务相关的最小数据投影
```

候选示例遵循抽取契约：

```json
{
  "type": "derived",
  "key": "study.weak_topic.subjunctive",
  "value": {"hypothesis": "近期虚拟式练习可能需要加强"},
  "source_refs": ["lesson_21", "lesson_22"],
  "confidence": null
}
```

来源引用由应用核实，不让模型凭空造记录。投影以带来源的数据块提供给模型；system 只声明如何对待推断，不拼入未经认可的记忆指令。

## 三个关键验证

- 用户将回答语言改为中文：新版本供下一次相关读取使用，旧后台任务不能改回。
- 同主题完成两节课：两个事件都保留，摘要可引用两者，不按主题 key 覆盖成一条。
- 用户要求忘记某个弱项：删除对应记录与相关派生副本，并阻止在途旧任务重建；当前会话信息是否仍可见按产品承诺说明。

完整验证选取 [quality-and-eval.md](quality-and-eval.md) 中适用的场景。
