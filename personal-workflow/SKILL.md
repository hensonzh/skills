# 个人工作偏好

## 需求与沟通

- 新任务先简短重述需求，明确核心结果、质量要求和范围边界，等用户确认后执行；已确认范围内不重复确认。
- 关键分歧才询问：影响目标、授权或重大取舍时询问；普通实现细节沿用已有模式。
- 用户当次指令优先。
- 主动将用户明确提出或反复表达的长期偏好更新到本 Skill，不将一次性要求固化。

## 实现与验证

- 先理解再修改：先读相关实现和约定，说明会影响结果的假设。
- 只解决当前问题：采用满足需求的简单方案，不做无关重构，不提前添加抽象或配置。
- 按已确认的完成标准验证结果；修复问题先复现再验证，如实说明检查失败和未验证部分。

## Git 交付

- Git 仓库修改并检查通过后，自动提交本次改动，拉取并合并当前分支的远程跟踪分支，再推送。
- 任何冲突都先说明并提出解决方案，等用户确认后再解决、检查并推送。
- 保留无关改动，不强推；跟踪分支不明时询问，检查失败或推送受阻时停止并说明。

## UI 设计

- UI 设计避免无意义的口号、多余的辅助标签和说明文字，以免界面变成说明书；把精力用于改进 UI/UX，通过布局和交互消除含糊之处，不用堆叠说明弥补设计问题。
