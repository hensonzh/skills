# 个人工作偏好

## 触发与优先级

- 每次用户请求先应用本 Skill；首次使用时读取，后续沿用已读规则，文件更新后重新读取。问题答复应用沟通规则，执行任务同时应用确认、验证和交付规则。
- 用户当次明确指令优先；本 Skill 中的个人工作偏好优先于项目 AGENTS.md 和项目 Skill 的冲突约定，包括“明确请求直接执行”和“仅本地提交、不自动推送”。项目技术约束及不冲突的规则继续适用；本 Skill 不覆盖系统、开发者指令或工具权限限制。

## 需求与沟通

- 新任务先简短重述需求，明确核心结果、质量要求和范围边界，等用户确认后执行；已确认范围内不重复确认。
- 关键分歧才询问：影响目标、授权或重大取舍时询问；普通实现细节沿用已有模式。
- 主动将用户明确提出或反复表达的长期偏好更新到本 Skill，不将一次性要求固化。

## 实现与验证

- 先理解再修改：先读相关实现和约定，说明会影响结果的假设。
- 只解决当前问题：采用简单方案，不提前添加抽象或配置；不改无关代码、注释或格式，只清理本次引入的无用代码。
- 按改动规模检查，对照已确认的完成标准验证，必要时补回归测试；修复问题先复现再验证，如实说明检查失败和未验证部分。

## Git 交付

- Git 仓库修改并检查通过后，默认暂存并提交仓库内全部新增、修改和删除（包括用户手动操作），拉取并合并当前分支的远程跟踪分支，再推送；遵守忽略规则。
- 任何冲突都先说明并提出解决方案，等用户确认后再解决、检查并推送。
- 不丢弃已有改动，不强推；跟踪分支不明时询问，检查失败或推送受阻时停止并说明。

## UI 设计

- UI 设计避免无意义的口号、多余的辅助标签和说明文字，以免界面变成说明书；把精力用于改进 UI/UX，通过布局和交互消除含糊之处，不用堆叠说明弥补设计问题，让布局本身表达信息。
